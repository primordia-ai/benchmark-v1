# benchmark-v1
Benchmarking CRISTAL architecture vs LLM-based analysts.


## Setup

Setup is straightforward with [poetry](https://python-poetry.org/docs/).
```bash
# In project root
poetry install
```
This will install our `src` modules (`CRISTAL`, ...).  
You can then use simply import our src structures as `CRISTAL.llm`, `CRISTAL.utils` , etc.

### Env and Package management

`poetry` provides an isolated python environment with your package dependencies.

You can spin up your env 
~simply with `poetry shell`~ with `eval $(poetry env activate)` (see [here](https://python-poetry.org/docs/managing-environments/#activating-the-environment)). Or you can execute a one-off command in your env with `poetry run <my_script>`.

`poetry` is also a package management tool.  
It bundles env dependencies in the `poetry.lock` file.

If you need to add a new dependency, run
```bash
poetry add <package>
```
which will update the env and `pyproject.toml`.

Or if you want finer control over the package version for instance,
you can update `pyproject.toml` directly, then run `poetry update`.

## Using LLMs

### Open-source with Ollama
`ollama` allows one to use LLMs locally in an easy way.  
See their [docs](https://github.com/ollama/ollama) for setting up, but basically you just  
  1. Download the app (or command line utility)
  2. Install the package you want with e.g. `ollama pull llama3.2`
  3. Run the service through the app, or from CLI: `ollama run llama3.2`

### External API
For external models (GPT, Claude, Gemini), set your API key in `.secrets.json` (see `template_secrets.json` for format), and yes, `.secrets.json` is gitignored.  

### Creating and registering new LLMs
Creating and registering new LLMs is easy.

  1. Create your class in a logical place, and inherit the base class `LLMBaseClass`.
  2. Override the required methods
  3. Register it by adding it to `AVAILABLE_MODELS` in `src/CRISTAL/llm/__init__.py`
  4. Bonus points for setting its `context_window`, but this isn't necessary at the moment.

## `nltk`
The `nltk` package provides some tools for tokenizing. After installing it, you need to download the `punkt_tab` set for it. See [here](https://www.nltk.org/data.html) for how it selects the download location and if you might like to alter that. To download:
```python
import nltk
nltk.download('punkt_tab')
```

## Index

`data`: Synthetic data, ground truth data, etc. Data that is used for LLM input (even that which has been generated by LLMs) should be saved here, not in `results`. 

`models`: Save states of models and their belief arrays etc.

`results`: Experimental results and figures for reporting.
